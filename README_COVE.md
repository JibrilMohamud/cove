# Cove — Bookstore & Reading Room

A public-domain eBook and audiobook application built with React, TanStack Start, a Worker API, SQLite/D1, R2 media storage, and Supabase Auth. The active application is in `src/features/fore`.

## Commercial delivery and notifications

Commercial EPUBs now use entitlement-aware, short-lived delivery grants backed by Cove-controlled object storage rather than permanent signed URLs. Purchase ownership is snapshotted against immutable publication versions, with explicit recall/distribution controls, entitlement-scoped device/download limits, annotation-version anchors, and Biosync asset-version validation. Cove also has a durable in-app/email/Web Push/mobile-push-ready notification event/outbox pipeline for commerce, publishing, royalties, moderation, and security events. See `docs/NOTIFICATIONS_SECURE_DELIVERY_VERSIONED_OWNERSHIP.md`.

## Included in this update

- **Commercial catalog foundation:** Cove no longer treats a Gutenberg row as the bookstore identity. Public-domain source records are staged in `gutenberg_source_cache`, then normalized into Work → Edition → Product → Offer records with first-class contributors, publishers/imprints, series, categories, languages, identifiers, assets/versions, accessibility metadata, territories, rights and prices. The existing Gutenberg numeric ID remains only an external identifier so current URLs keep working.
- **Commercial rights enforcement:** rights are now a fail-closed legal availability layer, not a warning. `rights_grants` models edition, rightsholder, contract, snapshotted territory scope, exact format, sales channel, start/end dates, license type/exclusivity, language rights, DRM requirement, subscription/library permission and structured promotion restrictions. Active deny grants override allows. Storefront browsing uses the network-derived storefront country (`CF-IPCountry` on Cloudflare, with a configurable local fallback), while checkout must match the billing country used for tax/payment. Search, taxonomy, merchandising, recommendations, product detail, samples, Gutenberg acquisition and full-file delivery all use the same authoritative projection/resolver. Every checkout line snapshots the exact grant and constraints used and persists an auditable rights decision. Retail rights never imply subscription, library or audiobook rights. Customer-visible subscription/library badges are resolved per storefront territory rather than copied from edition metadata.
- **Federated jurisdictional public-domain catalogs:** Project Gutenberg US, Project Gutenberg Canada, Project Gutenberg Australia, and reviewed Project Gutenberg Europe material are independent source adapters with independent leases/backoff, provenance and country-scoped grants. Canada activates only `CA`, Australia only `AU`, and European material requires explicit per-item ISO countries—there is no blanket `EU` grant. Native regional EPUBs are preferred; trusted same-source HTML-only editions are asynchronously normalized into Cove-owned EPUB3 files. Source exceptions, permission-only notices, incomplete trademark/licence cleanup, evidence changes, and missing canonical objects fail closed. See `docs/GUTENBERG_FEDERATION.md`.
- **Entitlements instead of library-as-ownership:** access rights now live in `entitlements`; `reading_states` controls whether an entitled product is shown in My Library and stores progress. Removing a title from My Library keeps the entitlement. Personal imports receive private product + entitlement records. Commercial `fore_<uuid>` products cannot be added without an existing purchase/loan/subscription/gift/publisher entitlement.
- **No canonical book snapshots:** the old `library`, `uploads`, `shelf_books`, and `completions` tables are migrated and retired. Shelves and completion history reference product IDs. Search uses `catalog_search_documents`, a generated discovery document, while canonical metadata stays normalized. Raw Gutenberg JSON remains only at the supplier-cache boundary.
- **Commercial search:** storefront search no longer scans serialized metadata with `%LIKE%`. Production search uses Meilisearch 1.36+ with weighted title/author/series/ISBN/publisher/category fields, typo tolerance, prefix search, synonyms, disjunctive facets, catalog-oriented query matching, commercial filters/sorts and an optional hybrid semantic layer. D1 FTS5 is a live independent fallback with Unicode search, English stemming, exact identifier boosts, synonym expansion and bounded typo correction. An outbox keeps the external index eventually consistent, private imports are suppressed, review signals refresh ranking data, and query/click analytics validate result impressions before accepting clicks.
- **Commercial storefront and browse architecture:** Cove now distinguishes release, publication, catalog-addition, update, and preorder/coming-soon dates instead of presenting one ambiguous “newest” signal. Gutenberg subjects remain source metadata; Cove owns a versioned hierarchical retail taxonomy with editable mapping rules, manual editorial overrides, dynamic product counts, nested `/ebooks/...` category routes, and first-class edition/author/series/publisher/imprint pages with stable public slugs and redirect-safe aliases. Author pages surface their series/collections, publisher pages surface imprints and series, imprint pages preserve publisher lineage, and catalog/product links emit canonical human-readable entity URLs rather than opaque IDs when a slug exists.
- **URL-addressable discovery:** search and filters live in the URL, so filtered results are shareable, browser Back/Forward restores state, and the store exposes durable `/bestsellers`, `/new-releases`, `/preorders`, `/deals`, category, `/edition/...`, `/author/...`, `/series/...`, `/publisher/...`, `/imprint/...`, and campaign pages. Public entity slugs are collision-safe and historical slugs remain aliases instead of being reassigned to another entity. Curated/entity pages get canonical SEO metadata while arbitrary search/filter combinations are kept out of the index with `noindex,follow`.
- **Storefront merchandising CMS:** the hard-coded “Cove Edit” has been replaced by scheduled campaigns, stable page slots, manual/dynamic collections, query-driven and personalized placements, territory/language/audience targeting, campaign priorities, sponsored labeling, deterministic weighted experiments, server-side impression/click measurement, audit history, and CMS-managed landing-page copy. Impressions require 50% visibility and are deduplicated per page view; clicks require a prior valid impression. Storefront operations use account-backed staff RBAC + MFA; machine ingestion uses separately scoped service principals.
- **Commercial recommendation platform:** Cove now runs a multi-stage recommender with content, co-read/collaborative, user-affinity, series, followed-author, wishlist-price-drop, reread, editorial, popularity/trend, and optional external ML/vector candidate sources. A second-stage ranker applies model-versioned source weights, explicit negative feedback, diversity and controlled exploration; recommendations are rights/territory aware, exclude private uploads and suppress repeated SKUs across rails. Visible impressions/clicks use validated request attribution, high-frequency behavior events are idempotent, and users can disable activity learning/personalized search or reset the learned profile. The operator CMS includes model registry/activation, ranking experiments, candidate-neighbor rebuilds, queue health, latency/scorer diagnostics, and 30-day CTR/catalog-coverage/source-diversity evaluation.
- **Commercial product detail:** product pages now resolve live rights and effective offers rather than assuming every catalog title is free. They expose structured publisher/imprint/series/ISBN/release/language/length/EPUB/DRM/download/accessibility metadata, current promotions, public ratings, retail taxonomy and ranking data. A missing or expired offer renders as unavailable, never as `$0.00`. Full-file controls appear only when the reader already has lawful full access.
- **Protected previews/samples:** publishers can configure percentage- or chapter-bounded preview policies from the storefront operator console. Commercial samples are server-derived EPUBs keyed by source asset version + preview-policy version; the derivative contains selected spine documents plus only the safe presentation assets those documents reference, rather than hiding later chapters client-side or shipping the complete publisher EPUB. Commercial source URLs are never fetched on a customer request: non-Gutenberg assets must already be in Cove-controlled object storage. Preview reading state is isolated from ownership; when full access is later granted Cove carries over the CFI anchor, but deliberately does not copy the sample-relative percentage.
- **Commerce wishlist, cart, and checkout:** Wishlist is separate from reading shelves and stores live offer state, per-title price-drop/sale/release/preorder alert preferences, acquisition attribution, sharing state and conversion markers. Share links are revocable/rotatable and expose no private reading data. Wishlist alerts and cart snapshots always re-resolve current territorial rights and offers; lost rights make an item unavailable rather than preserving stale purchasability. The account-persistent cart feeds a server-authoritative Stripe checkout with regional offer revalidation, currency consistency, stale-price detection, promotions, gift/store credit, Stripe Tax, PaymentIntents, Payment Element, purchase entitlements, receipts/invoices, refunds, disputes, reconciliation, and accounting records.
- **Commerce boundaries:** the schema separates prices, orders/items, payments/refunds, licenses/devices, subscriptions/catalog/usage, publisher accounts/users, royalty contracts/events, ledger entries, payouts and statements. Retail checkout is active when real Stripe server/webhook secrets are configured. Cove Publishing now supplies publisher onboarding/readiness, versioned royalty contracts and payout-facing controls; subscription billing remains a separate future system and external KYC/tax/bank providers still fail closed until configured.
- **Ratings and reviews:** 0.5–5 stars in half-star steps, each with the requested caption; optional written review; private by default; public publishing; spoilers; edit/delete; one rating per reader per book. Private ratings never enter public averages or feeds. Existing personal reviews migrate privately.
- **Community:** public averages and distributions, exact-rating filtering, written-reviews-only filter, pagination, newest/popular/trending/longest/shortest sorting, idempotent hearts, reporting and an operator moderation API. No replies. Popular means total hearts; trending means hearts from the last seven days, then recent reviews.
- **Shelves:** named lists with descriptions, private/public visibility, stable sharing URLs, ordered membership, reorder/remove controls, and add-to-shelf actions. Personal imports cannot enter public shelves.
- **Stats:** 7/30/90/365-day and all-time views; reading/listening time, average session length, estimated weighted words per minute, completions and annual goals, activity timeline, saved vocabulary, genres/subjects, average measured book length and estimated English readability. Listening time is excluded from reading pace. A JSON export contains the current reader's data only.
- **Audiobooks:** a separate navigation destination (the Bookstore is eBooks only); human/computer/unclassified filters; search; complete multi-track playback; speed, skip, sleep timer and lock-screen controls; versioned account and device bookmarks; offline audio; audio ZIP; and combined text + audio packages.
- **Downloads and private exports:** book bytes and personal reading data are separate products at the data boundary. **Download book** uses a dedicated content-export endpoint and emits only the entitled EPUB; it separately enforces the edition asset's publisher-controlled `downloadable` flag instead of treating “can read in Cove” as permission to export the source file. **Export reading data** emits only the signed-in reader’s highlights/notes, saved words, positions and reading history and remains available for reader-only editions; **Cove private backup** deliberately combines both, carries a strong sharing warning and private-backup manifest, and is available only when EPUB export is permitted. Export audits record only user/product/kind/time—never note text or archive contents. Explicit browser offline storage, original audio ZIPs and BioSync downloads remain separate download flows.
- **Biosync:** bidirectional word-level handoff backed by exact EPUB and audio hashes. Independent ASR must match the exact EPUB text with at least 0.72 per-word confidence and 80% interior coverage before a map can be published. Unmatched introductions, music, omissions, and long pauses have no handoff; the player never guesses from whole-book percentages.
- **Accounts:** username/email + password, password visibility control, email syntax validation, mandatory provider-side email confirmation, reset flow, HttpOnly server sessions, username uniqueness, and optional Google OAuth. Existing reading data migrates only when a verified provider email matches the trusted prior identity.
- **Hardening:** ownership checks, conservative rights filtering, bounded input/rate limits, spoiler/report flows, real media byte ranges, checksum-verified R2 writes, retries for offline activity and exclusion of private API data from the service worker cache.

## Operations and launch boundaries

The audiobook worker consumes Gutenberg's weekly bulk RDF catalog plus daily feed, re-checks the exact US public-domain rights statement, imports every original track, pins the paired EPUB, and publishes only automatically checked timing maps. Work is leased, retryable, resumable, and content-addressed. A failed map remains playable audio with independent bookmarks. See `docs/BIOSYNC.md` and `FORE_SETUP.md`.

The repository includes the continuous worker, but a scheduler and worker runtime must remain operated. Supabase email confirmation and Google must also be enabled with production redirect URLs before public account registration is opened. Production scale additionally needs moderation staffing coverage and queue/SLA operations, backup/restore drills, observability, load tests, account-erasure controls, and a broader device/accessibility pass. The recommendation platform is implemented, but production ML training/embedding infrastructure remains optional and separately operated. There is no social reply system. Commercial checkout is implemented but intentionally fails closed until a real Stripe secret key and webhook signing secret are configured; launch also requires Stripe Tax registrations/settings, Radar/payment-method policy, webhook monitoring, and scheduled reconciliation appropriate to the jurisdictions Cove actually sells into.

### Commercial checkout / Stripe

Cove now includes a server-authoritative commercial checkout based on Stripe PaymentIntents and the Payment Element. The browser receives only the publishable key and PaymentIntent client secret; a placeholder `STRIPE_SECRET_KEY` keeps charging disabled until deployment is explicitly configured. Commerce includes persistent carts and Buy Now, regional offer revalidation, Stripe Tax, promotions, gift cards/store credit, authorization/manual capture support, idempotent order creation, payment recovery, receipts/invoice records, mixed-tender partial/full refunds, dispute/chargeback tracking, Stripe Radar risk outcome capture, reconciliation, order history, an immutable accounting ledger, and CSV accounting exports. Finance operations use individually provisioned finance staff capabilities with MFA and do not share storefront or ingestion credentials.

## Commercial pricing and multi-party finance

Cove's retail price is now a reproducible pricing decision rather than a mutable `offers.amount_minor` lookup. Each checkout line resolves territory, target currency, active schedule, FX rate/source, floors/ceilings, promotion funding, and preorder-price guarantees; the resulting decision is persisted and referenced by the order item. Regional FX values are stored as versioned rates in integer parts-per-million so historical orders never depend on a later exchange-rate refresh.

Publisher/creator economics are also event-based. Finance parties and versioned royalty contracts define calculation basis, Cove commission, payment terms, reserves, withholding, and split beneficiaries. A paid order creates immutable royalty accrual events; refunds and lost chargebacks create reversal events instead of modifying the original sale. Publisher-funded, Cove-funded, and shared promotions are distinguished when calculating royalty basis. Payout batches select only matured accruals, require approval, and can only become paid when an external bank/provider settlement reference is recorded.

The commerce ledger remains append-only double entry. Royalty expense/payables, withholding liabilities, reserves, and cash payout postings are kept in the same audit trail as customer payments, tax, refunds, Stripe fees, and disputes. The staff Commerce & Finance console exposes FX rates, scheduled regional prices, finance parties, royalty contracts, payout batching/approval/settlement, and the existing reconciliation/accounting exports.

## Rights management and territorial offer enforcement

Migrations `0014_commercial_rights_management.sql`, `0015_rights_channel_projection.sql`, and `0016_contract_territory_engine.sql` add the commercial rights stack: rightsholders, grant lifecycle (`draft`, `active`, `suspended`, `revoked`, `expired`), explicit allow/deny decisions, contract/language restrictions, exclusivity, promotion restrictions, channel-scoped offers, a unified fail-closed retail/subscription/library availability projection, and append-only legal evidence. The matching decision is **edition + resolved market + format + sales channel + effective date + contract language scope**. Missing rights are a denial; an active deny overrides an allow; the delivered asset must satisfy the grant's DRM requirement.

`0016` adds a global territory registry and contract-style scope expressions. System templates include `WORLD`, `EU`, `EEA`, `ANZ`, `US_CA`, and `GB_IE`; operators can build nested custom sets, direct country includes/excludes, and historical-entity expressions such as `#SU`. Legacy aliases such as `UK` canonicalize to `GB`. Historical entities have dated successor mappings, and ambiguous reused codes such as `CS` require an as-of date. A `WORLD excluding GB, AU` grant is therefore expanded into exact modern markets before activation.

Territory sets are reusable drafting templates, **not live pointers inside executed grants**. When a grant is saved, Cove materializes the resolved country membership into `rights_grant_territories` and writes an append-only `rights_grant_scope_snapshots` record. Editing `WORLD`, `EU`, or a custom set later does not silently rewrite an existing contract. Contract-level language allow/deny rows can additionally scope by format, channel, and dates. Conflict analysis compares overlapping territory snapshots, dates, formats, channels, language scope, rightsholders, and exclusivity; exclusive collisions are rejected before activation while other suspicious overlaps are surfaced to operators.

The legal right and the customer's entitlement are intentionally separate. Rights decide whether Cove may expose, sample or newly distribute a product in a storefront. Once a purchase/loan/subscription entitlement has lawfully been issued, that entitlement remains the access authority even if the customer later travels or a future-sale grant expires. Order items retain `rights_grant_id`, `rights_decision_id` and `rights_snapshot_json`, including contract, scope, exclusivity, and language evidence, so historical transactions do not depend on mutable current contracts.

Use **Commerce → Rights, contracts & territorial availability** in `/staff/storefront` (protected by finance/commerce staff RBAC + MFA) to manage rightsholders, territory sets, contracts/languages, grants, bulk scope expansion, conflict review, and the same availability resolver used by customer flows. Promotion restrictions support discount prohibition, free-promotion prohibition, maximum discount basis points, minimum customer price, excluded promotion types and explicit-rightsholder-approval requirements.

## Cove Publishing self-publishing foundation

Cove now includes a separate creator control plane at `/publishing` and an operations console at `/staff/publishing`. Creator drafts and uploads are intentionally isolated from retail data until identity/tax/payout readiness, rights/metadata setup, required asset validation, immutable submission and staff approval are complete. Publishing runs an explicit Draft → Validation → Submitted → Automated Review → Human Review/Approved → Scheduled/Preorder → Live/Updated lifecycle, with Suppressed/Takedown/Retired enforcement states. Each approved revision produces an immutable publication-version manifest and append-only activation history rather than overwriting the prior edition.

Existing owners default to `auto_update`, so an activated v7 is delivered without repurchase, while `manual_opt_in` and `preserve_purchased_version` pin entitlements to a specific immutable publication version. Rollback reactivates an older manifest and commercial terms but cannot bypass an active suppression/takedown/retirement. Scheduled versions stage rights, royalty and offer records without activating them early, and rights conflicts are rechecked at activation time.

Uploads are stored under a quarantine namespace and validated through leaseable/idempotent jobs. Malware scanning, official EPUBCheck, rendering and device-compatibility checks are modeled as real required external validators and fail closed when unavailable. Staff moderation uses signed-in SSO/MFA-bound identities, granular RBAC, review/title/author/publisher/copyright/fraud/impersonation queues, notes, sanctions, appeals, escalation, emergency suppression, repeat-offender signals and append-only staff/action audit history. See `docs/PUBLISHING.md` for the worker/provider contract and privacy boundary.

## Creator commerce: royalty engine, reporting, preorders, and promotions

Cove Publishing now uses a versioned contractual royalty rules engine rather than a hard-coded marketplace percentage. Contract versions and ordered rules can vary by product/edition/publisher, territory, format, channel, price band, rights basis, promotion/funding source, distributor, and subscription plan. Every resulting calculation snapshots its exact inputs, selected rule, contract-version hash, fees, taxes, discount funding, commission, royalty pool, party allocations, reserve/withholding and payment availability; historical economics are immutable and corrections use new versions/reversal events.

The creator dashboard exposes current and period sales, title/territory performance, refunds, estimated royalties, preorders, subscription/audiobook/library consumption, wishlist/conversion proxies, promotion funnels, payouts, monthly statements, CSV exports and tax-document records. Final statement revisions are append-only and definitive statement CSVs are cutoff-bound and hashed so later-posted activity cannot silently rewrite an older report.

Future-dated publications support charge-now preorders with no entitlement until release, duplicate-preorder protection, customer/publisher cancellation, lowest-price refund jobs, audited release-date changes, delivery-readiness checks, publisher incidents and automatic failure refunds. Promotions support scheduled price drops, deals, genre/publisher sales, coupons, free/first-in-series/bundle/launch/seasonal/countdown campaigns, explicit Cove/publisher/shared funding, rights/restriction validation, staff approval, budget/redemption controls, attribution and preorder-price interactions. See `docs/CREATOR_COMMERCE.md` for the accounting, worker, and operational contracts.

## Commercial author identity, review provenance, Cove charts, and retail telemetry

Migrations `0028_retail_intelligence_author_review_ranking_analytics.sql` and `0029_retail_intelligence_hardening.sql` add Cove's retail-intelligence layer. Stable contributor IDs are extended by verified commercial author profiles with immutable submitted revisions, biographies, portraits, controlled public links, publisher/imprint affiliation, catalog-derived bibliography/series/upcoming releases, follow preferences, and durable release/preorder alert jobs.

Public reviews freeze access provenance at first submission (`verified_purchase`, `subscription_reader`, `free_promotional_copy`, `gifted`, `publisher_author_copy`, or `sideloaded_unverified`). Provenance is displayed to readers but internal trust scores are not. Review/rating and heart abuse signals feed moderation and ranking influence rather than automatically deleting speech. Anti-brigading/vote thresholds are themselves immutable, versioned policy records, and account sanctions/appeals remain part of the normal staff moderation workflow.

Commercial browse rankings are calculated only from Cove activity and never from Project Gutenberg `download_count`. The store supports bestselling, trending, most-read, most-wishlisted, new-and-noteworthy, and top-rated charts. Client search/view telemetry is accepted into the warehouse stream but down-weighted, freshness-checked, capped per actor and product, and materialized into unique-actor metrics before it can influence behavioral charts. Purchases, refunds, reading completion, review submission, wishlist/cart actions and other authoritative facts are emitted by Cove services. Ranking policies and generated snapshots are versioned/append-only for reproducibility.

`retail_events` is the operational analytics stream and is intentionally separate from reader-facing personal reading-state data. Every event fans out through a leaseable warehouse outbox with retry/dead-letter behavior. See `docs/RETAIL_INTELLIGENCE.md` for event authority, worker cadence, privacy boundaries, anti-gaming rules, author alerts, and chart semantics.

## Fraud risk and tax compliance

Migration `0034_fraud_risk_tax_compliance.sql` promotes fraud and tax into durable commercial domains.
Cove now has versioned risk policies, immutable risk events/assessments, entity-link evidence, explicit
holds and manual investigation cases covering buyer/account-takeover fraud, publisher/content/payout
fraud, subscription-reading manipulation and community brigading. The controls are wired into checkout,
commercial EPUB and audiobook access, publishing review, royalty credit and payout release rather than
existing only as dashboard signals.

Tax is intentionally split in two. Customer sales/VAT/GST-style transaction tax is delegated to Stripe
Tax and mirrored into Cove's immutable tax evidence/transaction/reversal/reconciliation records. Publisher
payee tax uses provider-verified tax profiles, effective-dated withholding/treaty rules, payout holds and
annual reporting-period records; Cove does not store full tax identifiers or tax forms. See
`docs/RISK_TAX_COMPLIANCE.md` for provider boundaries, webhook signing and operational runbooks.

- **Global storefront + production control plane (0035):** Cove now resolves a server-side country/locale/currency/rights context, supports versioned translated UI bundles and RTL presentation, localized categories, regional pricing/payment policy and region-aware merchandising/recommendations. Human administration uses account-backed staff RBAC + MFA; workers use independently rotated, hashed, scoped service-principal credentials. Production operations include structured request/error telemetry, W3C trace IDs, SLO measurements, dependency probes, incident/alert delivery, recoverable leased queues with DLQs, verified backup and measured restore-drill evidence, explicit RPO/RTO, guarded blue-green/canary deployment records, migration rollback controls, non-charging checkout synthetics and capacity-test evidence.
