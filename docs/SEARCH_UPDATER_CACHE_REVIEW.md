# Search, catalog updater, and cache review

## Findings and changes

| Area              | Problem found                                                                                                                         | Change                                                                                                                                                                                                                                                                |
| ----------------- | ------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Search filters    | A comma-separated first value was also retained as a literal; pagination collapsed repeated keys.                                     | Split list-valued codes correctly, keep human labels containing commas intact, and retain repeated keys in next-page links.                                                                                                                                           |
| Suggestions       | Identifier matching used a nonexistent ranking alias; punctuation could fall through to broad browsing.                               | Rank identifiers without the text-match alias; punctuation-only search returns no results.                                                                                                                                                                            |
| Typo correction   | Correction ran only on page one, so later pages of a corrected search could be empty.                                                 | Apply the same correction when the original query has zero matches, including later pages. Use a stable product-ID tie-breaker.                                                                                                                                       |
| Search work       | Every catalog request scanned source counters and every page repeated seven facet aggregations.                                       | Replace seed COUNT with an existence lookup; return only a small updater summary; materialize the shared candidate set once for unfiltered facets; cache facets and page IDs for 10 minutes, rechecking live page eligibility before hydration.                       |
| Browser caching   | Query keys omitted storefront context, old requests kept running, and bundled seed books flashed before real results.                 | Include market, locale and currency in the relevant query keys; consume cancellation signals; remove seed placeholders; use five-minute catalog/context queries, 15-minute storefront pages and 30-minute taxonomy queries; client navigation preserves these caches. |
| Public API cache  | Edge lookup failure could break availability; only the first language preference was keyed; cached analytics/request IDs were shared. | Preserve the whole language header and country, sort parameter keys, bypass accounts, unknown cookies, auth and ranges; key safe guest preferences separately, recover from cache failure, and give cache-hit searches new impression IDs.                            |
| Deployment cache  | The backend uses a workers.dev origin, where edge cache behavior should not be a dependency.                                          | Use a bounded D1 application cache on that origin and an edge cache on custom domains, with D1 fallback if edge reads fail.                                                                                                                                           |
| Scheduled updater | Browsing kicked ingestion, state reads followed by unconditional claims raced, and asset limits were larger than requested.           | Keep ingestion in scheduled/manual jobs, claim US/regional work and individual downloads atomically, fence cursor updates, and honor the requested download limit.                                                                                                    |
| Source fairness   | A limit below the number of regional sources could favor alphabetically earlier queues.                                               | Rotate based on each source's last actual asset attempt.                                                                                                                                                                                                              |
| Job bounds        | Retries and asset work could start beyond the batch budget; long Retry-After delays were clamped and retried prematurely.             | Pass the batch deadline to upstream/body fetches, check it between chunks and assets, and persist long upstream retry windows in scheduler backoff.                                                                                                                   |
| External indexing | A document updated during upload could have its new outbox entry deleted by the old upload.                                           | Serialize sync jobs with a lease and acknowledge only the uploaded change token. Batch deletes replace per-document delete requests.                                                                                                                                  |

## Cache boundaries

Public response TTLs: catalog 300 seconds; suggestions 60; book metadata 60; taxonomy 1800; storefront pages 900; audio lists/details 300; service status 30. Responses sent to browsers stay `no-store`; private account data is never written into the shared response cache. There is no stale-response fallback after expiry or a rights/query failure.

The D1 public-response namespace is limited to 128 entries and 256 KiB per response. The facet namespace is separately limited to 128 entries; the public page-ID namespace to 256. Each write recycles expired/oldest entries atomically, so a full cache still accepts new URLs. Scheduled cleanup removes up to 512 expired entries per tick, using an expiry index. Cache trouble falls back to the normal authoritative handler. Cache-hit search analytics retain the normal guest rate limit and generate fresh impression UUIDs; analytics failure does not fail a successful search.

Facet reuse does not cache personalization. The facet key includes the effective rights country, currency, all filters and the effective text expression. Its ten-minute TTL bounds count/price-label staleness. Page-ID hits hydrate current metadata and prices; full public-response hits revalidate current product/territory eligibility. Client presentation may remain fresh for five minutes. Cache-retention timers run only in the browser; SSR uses infinity so server renders do not retain query caches on long-lived timers. Purchases and downloads continue to recheck authoritative rights and prices; cached presentation is not an entitlement.

## Update integrity

Migration `0045_catalog_update_leases_and_search_queue.sql` adds US updater and external-index leases, a per-source asset-attempt timestamp, outbox change tokens, and queue/cache indexes. Existing regional source lease columns are now claimed conditionally. Leases expire so a crashed job can recover; late holders cannot replace another holder's cursor. Download claims use conditional updates so workers cannot fetch the same queued item concurrently.

Metadata and assets remain resumable. Only processed regional chunks advance the source cursor. A batch deadline stops new work and bounds upstream fetch/body time; a short database batch or object-store write already underway may finish afterward. The scheduled harvester continues crawling unseen pages and drains asset work, then refreshes completed source catalogs on their existing schedules. An upstream failure is retried with durable backoff rather than mistaken for completion.

Scheduled batches index US metadata pages first, with zero asset downloads and deferred external-index sync. They reserve up to 30 seconds (20% of a short tick) for regional metadata and assets; regional work runs once with a maximum 20-second request deadline. One asset drain uses the entire batch's bounded allowance, followed by an external-index sync. Regional processing still writes its durable chunks and retains its existing source-fairness rules.

Upstream metadata requests now have a 15-second per-attempt timeout, at most three attempts and the overall batch deadline. Metadata failures back off from one minute up to 30 minutes; longer upstream Retry-After windows remain authoritative. EPUB failures retain their more conservative existing backoff up to 24 hours. Successful metadata clears failure state and attempts. Asset-maintenance errors are reported separately and cannot turn a committed page into a failed metadata update. The actual number of started downloads survives a stage failure, preserving the allowance across regional/US drains in direct runs.

A background updater failure no longer adds a warning to a successful catalog search. Updater diagnostics remain available in ingestion/service status; genuine search fallback warnings remain visible. The frontend also tolerates an older backend's retry warning when usable books are present.

## Verification

`npm run test:search-updater-cache` exercises actual API/search/cache/updater functions against the complete SQLite migration chain. It covers repeated filters and pagination, identifier suggestions, corrected search pages, read-only browsing, bounded D1 cache size, edge/corrupt/expired-cache recovery, market/locale and private-request isolation, fresh cache-hit analytics IDs, external-index update races, exclusive updater claims, deadline handling, Retry-After behavior, and source fairness. The facet regression measures one cold aggregation query for the unfiltered candidate set, no additional aggregation queries for subsequent pages, and no full count query for a warm page. It also verifies suppression immediately invalidates both ID and full-response cache hits, a full cache admits the newest URL, metadata precedes EPUB transfers, asset-stage failures preserve successful cursors, and retry recovery clears errors.

The test runs in both persistence and security CI workflows. Existing service, regional rights, security, account/support and build regressions cover surrounding flows. This is structural and behavioral verification, not a production load benchmark. The browser catalog test opens a real edition and returns without another catalog, context or taxonomy request, verifies the JavaScript session survives navigation, and checks obsolete updater warnings are hidden. Firefox/WebKit and production latency/billing measurements remain rollout checks.

## Observed production baseline (2026-10-14 UTC)

A read-only request to the current production catalog returned 24 books in 12.679 seconds (first byte 12.543 seconds); its D1 search reported 6826 ms. The response included the background retry warning with ingestion status `failed`, despite successful indexed results. Storefront page metadata took 4.683 seconds. Both were backend cache misses and returned `no-store`/Vercel cache MISS. These measurements describe the old deployed code; local fixture timings are not a production performance forecast.

Deployment requires the persistence Worker and frontend changes together. The cache key version changes to avoid serving old retry-warning payloads; no new schema migration is needed for these catalog changes. The separate reader/CPU changes still require their documented migrations. After rollout compare cold/warm catalog latency and backend HIT headers, verify territory withdrawal/access behavior, inspect updater success/cursor progression, and observe the Vercel usage meter over time.
