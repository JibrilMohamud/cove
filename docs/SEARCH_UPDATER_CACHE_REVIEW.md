# Search, catalog updater, and cache review

## Findings and changes

| Area              | Problem found                                                                                                                         | Change                                                                                                                                                                                  |
| ----------------- | ------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Search filters    | A comma-separated first value was also retained as a literal; pagination collapsed repeated keys.                                     | Split list-valued codes correctly, keep human labels containing commas intact, and retain repeated keys in next-page links.                                                             |
| Suggestions       | Identifier matching used a nonexistent ranking alias; punctuation could fall through to broad browsing.                               | Rank identifiers without the text-match alias; punctuation-only search returns no results.                                                                                              |
| Typo correction   | Correction ran only on page one, so later pages of a corrected search could be empty.                                                 | Apply the same correction when the original query has zero matches, including later pages. Use a stable product-ID tie-breaker.                                                         |
| Search work       | Every catalog request scanned source counters and every page repeated seven facet aggregations.                                       | Replace seed COUNT with an existence lookup; return only a small updater summary; reuse public facets for 30 seconds across pages. Results and rights still use the live catalog.       |
| Browser caching   | Query keys omitted storefront context, old requests kept running, and bundled seed books flashed before real results.                 | Include market, locale and currency in the relevant query keys; consume cancellation signals; remove seed placeholders; use one transport retry layer and a 30-second query stale time. |
| Public API cache  | Edge lookup failure could break availability; only the first language preference was keyed; cached analytics/request IDs were shared. | Preserve the whole language header and country, sort parameter keys, bypass accounts/cookies/auth/ranges, recover from cache failure, and give cache-hit searches new impression IDs.   |
| Deployment cache  | The backend uses a workers.dev origin, where edge cache behavior should not be a dependency.                                          | Use a bounded D1 application cache on that origin and an edge cache on custom domains, with D1 fallback if edge reads fail.                                                             |
| Scheduled updater | Browsing kicked ingestion, state reads followed by unconditional claims raced, and asset limits were larger than requested.           | Keep ingestion in scheduled/manual jobs, claim US/regional work and individual downloads atomically, fence cursor updates, and honor the requested download limit.                      |
| Source fairness   | A limit below the number of regional sources could favor alphabetically earlier queues.                                               | Rotate based on each source's last actual asset attempt.                                                                                                                                |
| Job bounds        | Retries and asset work could start beyond the batch budget; long Retry-After delays were clamped and retried prematurely.             | Pass the batch deadline to upstream/body fetches, check it between chunks and assets, and persist long upstream retry windows in scheduler backoff.                                     |
| External indexing | A document updated during upload could have its new outbox entry deleted by the old upload.                                           | Serialize sync jobs with a lease and acknowledge only the uploaded change token. Batch deletes replace per-document delete requests.                                                    |

## Cache boundaries

Public response TTLs: catalog 90 seconds; suggestions 60; book metadata 60; taxonomy/storefront pages/audio lists and details 300; service status 30. Responses sent to browsers stay `no-store`; private account data is never written into the shared response cache. There is no stale-response fallback after expiry or a rights/query failure.

The D1 public-response namespace is limited to 128 entries and 256 KiB per response. The facet namespace is separately limited to 128 entries. The scheduled cleanup removes up to 300 expired entries per tick, using an expiry index. Cache trouble falls back to the normal authoritative handler. Cache-hit search analytics retain the normal guest rate limit and generate fresh impression UUIDs; analytics failure does not fail a successful search.

Facet reuse does not cache personalization. The facet key includes the effective rights country, currency, all filters and the effective text expression. Its short TTL bounds count/price-label staleness. Purchases and downloads continue to recheck authoritative rights and prices; cached presentation is not an entitlement.

## Update integrity

Migration `0045_catalog_update_leases_and_search_queue.sql` adds US updater and external-index leases, a per-source asset-attempt timestamp, outbox change tokens, and queue/cache indexes. Existing regional source lease columns are now claimed conditionally. Leases expire so a crashed job can recover; late holders cannot replace another holder's cursor. Download claims use conditional updates so workers cannot fetch the same queued item concurrently.

Metadata and assets remain resumable. Only processed regional chunks advance the source cursor. A batch deadline stops new work and bounds upstream fetch/body time; a short database batch or object-store write already underway may finish afterward. The scheduled harvester continues crawling unseen pages and drains asset work, then refreshes completed source catalogs on their existing schedules. An upstream failure is retried with durable backoff rather than mistaken for completion.

## Verification

`npm run test:search-updater-cache` exercises actual API/search/cache/updater functions against the complete SQLite migration chain. It covers repeated filters and pagination, identifier suggestions, corrected search pages, read-only browsing, bounded D1 cache size, edge/corrupt/expired-cache recovery, market/locale and private-request isolation, fresh cache-hit analytics IDs, external-index update races, exclusive updater claims, deadline handling, Retry-After behavior, and source fairness. The facet regression measures seven cold aggregation queries and no additional aggregation queries for the following cached page.

The test runs in both persistence and security CI workflows. Existing service, regional rights, security, account/support and build regressions cover surrounding flows. This is structural and behavioral verification, not a production load benchmark. Full browser/device QA and a future custom-domain edge-cache benchmark remain separate checks.
