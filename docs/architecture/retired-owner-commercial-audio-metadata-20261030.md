# Privately owned commercial audiobook metadata — staged QA, October 30, 2026

This branch retires SIX shared D1 writer sites from `src/features/fore/commercial-audio.server.ts` (profile upsert, narrator delete/insert, narration agreement creation/termination, agreement status refresh), replacing them with the typed `publishing.audio-metadata` owner command. Original SQL sites are traced in `docs/architecture/retired-owner-commercial-audio-metadata-lineage.json`. Exact updated source hash and a retained 18-site review are in `docs/architecture/retired-owner-commercial-audio-metadata-attestation-20261030.json`. The owner-required count is 239 on this PR, versus 245 before this step and 260 on main.

The isolated private owner re-evaluates the edition's current audiobook draft status and publisher membership, active audio policy and per-edition *staff-verified* narration/performance rights evidence. A command cannot select arbitrary SQL, a new owner endpoint, or an unverified evidence grant. Synthetic narrators must have labels before deletion. The owner returns a typed receipt; API caller cannot fall back to shared D1.

**Release-blocking limitations**: This metadata command is QA-lease-only; production has no owner binding. Narrator replacement is now one atomic D1 batch. The QA owner persists exact operation receipts and rejects same-key payload collisions. Before terminating an agreement linked to a published product, it rechecks membership and the current agreement, then commits a strongly consistent owner denial for every linked product *before* changing the D1 agreement row. Real isolated SQLite tests cover unauthorized denial, successful owner-first termination, rights-evidence gating, narrator atomicity, and exact replay. However, the crash window between primary-D1 commit and receipt-journal persistence still requires deterministic recovery; complete evidence-revocation races, geographic customer playback, and published grant reinstatement are not yet certified. A response lost after a DB commit could cause a duplicate agreement; this must be solved with durable idempotency keys before live operation. Termination of an agreement on a live title additionally requires an independently authorized immediate market/audio-access denial before D1 changes. No real production customer authority or rights reinstatement is certified. Do not merge into production until those guarantees, copyright restoration, live Stripe payment/refund, privilege retirement and protected rollback are proven. Tests and audit review never enable releaseApproval.
