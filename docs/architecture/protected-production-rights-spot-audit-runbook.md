## Failure #11: Cloudflare API 429 during actual live read-only audit

Manual [workflow run #11](https://github.com/JibrilMohamud/cove/actions/runs/43805021617) **did receive the protected read-only credential**, passed the offline checks, began the live audit, and returned `rights_spot_audit_http_429`. Cloudflare **throttled D1 API access**; the log contained no canonical-versus-legacy legal verdict and no authorization result. This is a **rate-limit failure, not proof that rights checks passed or failed**.

The staging fix introduces **one shared, bounded gate** for the entire spot audit: minimum **500 ms between HTTP request starts**; exactly the same verified `SELECT` and parameters are retried **only on 429**; conservative **20 / 40 / 80-second** fallback waits or the **longer** Cloudflare `Retry-After` value (seconds or HTTP date); maximum **three retries per SQL query**, **five total 429 responses**, **180 seconds total 429 waiting**, and **412 total HTTP attempts**. Existing caps of **400 authorized logical queries** and **eight products** still apply. If the server specifies a delay beyond the remaining budget, the job fails with `rights_spot_audit_rate_limited` rather than retrying too soon. Failed authorization (401/403), SQL errors, untrusted data, other HTTP errors and network errors **are not retried**. Body cancellation prevents retained response data, and only non-identifying numeric backoff events appear in logs. No D1 Write scope or relaxation of rights checks is added.

The fix is currently isolated on [draft PR #719](https://github.com/JibrilMohamud/cove/pull/719). **Do not merge into production main merely to run the fix:** the previous audit-only merge unexpectedly triggered a Vercel production deploy. First certify the provider-enforced automatic production promotion lock, per [release blocker #718](https://github.com/JibrilMohamud/cove/issues/718). If the operator reruns the existing main workflow before this fix is safely merged, it will still use the old script with **no backoff**, and may be rate limited again. A fully protected run using the corrected code is required for actual production legal evidence.

## Real withdrawal/denial coverage (protected audit v2)

[Production audit #19](https://github.com/JibrilMohamud/cove/actions/runs/43808080720) passed **eight positive matches and zero mismatches**, but all sampled products were allowed. It therefore offered no real-world evidence that withdrawals remain fail-closed.

Read-only primary D1 inventory on November 16 found **82,246 grants**: **81,909 active/allow**, **337 suspended/allow**, **zero explicit deny**, **zero contract-bound**, **zero versioned**, **zero timed** and **zero nontrivial-DRM grants.** The grant status is not itself a distribution entitlement: 5 of 5 inspected suspended examples had an **inactive product** and the current US availability view returned **false**. The protected sampler's exact negative SELECT was verified to retrieve **four** distinct-format valid product identifiers, with **zero writes**.

The protected audit now reserves **three independent groups**: **eight allowed** products, **four suspended/inactive** products, and **four Australian-only public-domain books that have no US rights grant**. Each suspended product must return the canonical reason `PRODUCT_INACTIVE` and be absent from the legacy US view. Each active Australian-only product must return the canonical reason `NO_ACTIVE_GRANT` and also be absent from that view. No group can borrow another group's successes; missing examples, duplicate IDs, invalid identifiers, unexpected reasons and either implementation exposing an unauthorized product all FAIL. Output is aggregate only (counts and reason codes), without product IDs or private authorizations.

Independent primary D1 evidence: **77,656 active US-public-domain grants**, **4,253 active Australian-public-domain grants** and **337 suspended Canadian-public-domain grants** (all `source_evidence_id` nonempty). Four real Australian grants had active products but **neither a US grant territory nor a US availability-row match**. This is real negative territorial evidence, not proof that Australian public-domain status means US public-domain status.

The v3 audit **does not certify** explicit-deny, contract, version, timed, language, DRM, paid-entitlement, immediate concurrent withdrawal, or the entire 82,247-product snapshot because those real production policy classes are absent or untested. It also cannot certify cross-query atomicity or production authorization writer readiness.

New separate non-live regression fixtures for exclusion, mandatory cohort coverage, exact reasons, and positive/negative overlap run on pull requests. This remains a **read-only** protected workflow. Do not grant any new rights, activate owner writes, change Stripe settings, or publish a product to make an audit pass.

## Limits and release safety

The audit evaluates at most **16** production product IDs (8 allowed + 4 suspended/inactive + 4 Australian territorial denials) and up to **400** single-statement read-only D1 queries. It never writes D1, changes legal grants, activates the production owner, changes Stripe payments, or modifies customer routing. It is not an atomic, full-catalog rights audit; it cannot certify missing contract/version/language/DRM witnesses, the 82,247-book authorization set, search parity, 503 elimination, four-region performance, Stripe LIVE or rollback.
